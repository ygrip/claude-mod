# jar

pi-jar's feel for Claude Code, in amber.

- **Ember**: pi-jar's pixel mascot above the prompt. Its mood follows the turn (happy or thinking while generating, busy during tools, waiting on a question, a hop when a turn ends, sleepy when idle).
- **Task perch**: the session's tasks beside Ember (`▸ Tasks · 3/7 done · current`). Press `t` with the band focused, or run `/jar tasks`, to expand it.
- **Spinner**: pi-jar's phrases ("Kindling a thought", "Tracing light through Bash").
- **Model roles + auto route**: subagents run on their role's model. Explore→scout, Plan→plan, reviewers→reviewer, implementers→worker, and `general-purpose` is sorted by a one-word Haiku classifier. A model named in the call always wins.
- **jar_discuss**: questions and answers between the main agent (moderator) and subagents, delivered straight to the addressee.
- **Auto advisor**: when the main agent repeats one call 4 times in 8, or 3 calls in a row fail, the `advisor` role gives a second opinion that joins the conversation. There is also the `jar_advisor` tool and `/jar-advisor [focus]`.
- **Amber look** in the desktop and mobile apps.

## Roles

Defaults: `scout: haiku`, `worker: sonnet`, `reviewer: sonnet`, `plan: opus`, `advisor: opus:high`, `classifier: haiku:low`, `task: @default`, `default: *` (inherit).

Override them in `~/.claude/jar/roles.json`, or per project in `.claude/jar-roles.json`:

```json
{ "version": 2, "roles": { "worker": "opus", "reviewer": "@plan:high" } }
```

Or run `/jar-roles set worker opus [--project]`, `/jar-roles clear worker`, and `/jar-roles list`.

## Settings

`/config` has three switches: auto route, auto advisor and Ember.

## Install

Clone the repo and point Claude Code at it in `~/.claude/settings.json`:

```json
{ "env": { "CLAUDE_CODE_PLUGIN_DIRS": "/path/to/claude-mod" } }
```

Check it with `claude plugin validate /path/to/claude-mod`.

## Development

Hook code is in `hooks/`, tests in `tests/`, and the `$.state` contract in `types/index.d.ts`. `.claude-plugin/types/` is generated by Claude Code and git-ignored. Validator rules the code follows (one unmatched `on` per event, atoms declared in the file that reads them) are listed in the plugin-authoring docs.
